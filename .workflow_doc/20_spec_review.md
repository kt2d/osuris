## 2.5 圧縮処理

| 仕様 | 実装 | 一致 |
|------|------|------|
| 移動対象は毎ステップ再計算 | `pushBlocksRight()` の while ループ内で `buildMovementSet()` 再呼出 | ○ |
| 移動対象の構築: BFS | `buildMovementSet()` BFS for 右隣が移動対象 | ○ |
| 移動判定: 右隣が空 or 移動対象 | `canMoveRight()` | ○ |
| 移動: 同時更新 | `moveRight()` newPositions を先に計算 | ○ |

| 縦方向ループ適用なし（壁スライド時のみ） | 圧縮中は `wrapX()` のみ（横方向）、`wrapY()` は使わない | ○ |
| 壁の移動ロジックと圧縮ロジックは分離 | `LeftWall` / `CompressionSystem` 別クラス | ○ |

# 3. 発見された問題

## 3.1 [重大] `LeftWall.advanceOccupiedBlocksInColumn()` の衝突検証欠如

**場所**: `src/LeftWall.ts` 行177-199

**仕様との不一致**:
> 圧縮アルゴリズム仕様「移動判定: 右隣セルが空である、または移動対象自身である場合のみ移動可能。1つでも移動できないブロックが存在する場合、その移動は失敗とする。」

この移動判定ロジックは圧縮処理（CompressionSystem）では正しく実装されている。
しかし、**壁の通常前進時**の固定ブロック押し込み（`advanceOccupiedBlocksInColumn()`）では、**ターゲット列が占有されているか検証されていない**。

**影響**:
1. 隣接列にブロックがある場合、ブロックが消失する（boolean grid での上書き）
2. ブロック消失によりフィールド状態が壊れる
3. 新ピースのスパン位置が占有され、即時ゲームオーバー

**再現フロー**:
```
1. I-piecel (type 0) が x=11, y=4 に生成 → セル: (11,4)(12,4)(13,4)(14,4)
2. 左壁 x=11 で接触 → 右へ押し込む
3. 左壁 x=12 で接触 → ピース右端 x=15、先 x=16(範囲外) → 押し込めず固定
   固定位置: (12,4)(13,4)(14,4)(15,4) ← 4ブロック
4. 左壁 x=13 に前進 → advanceOccupiedBlocksInColumn(13) 呼出
   → x=13 のブロックを x=14 へ移動
   → x=14 には既にブロックがあるが、チェックなしで field.set(14, 4, true)
   → 結果: (12,4)(14,4)(15,4) ← 3ブロックに減少（1消失）
5. 左壁 x=14 で圧縮トリガー
   → pushBlocksRight: x=14のブロックは右(x=15)が占有で移動不可
   → alignBlocksVertical: x=15のブロックを wallY(=0) 附近へ再配置
   → 結果: (12,4)(14,4)(15,0) などの散らばった位置
6. 新ピース生成: x=11, y=4 → セル (11,4)(12,4)(13,4)(14,4)
   → (12,4) と (14,4) に既存ブロックがある → 衝突
   → GAME_OVER
```

**修正方針**:
`advanceOccupiedBlocksInColumn()` の先頭で、全ターゲット位置が空か検証する。
一つでも占有されていれば、移動を中止して即座に return する。

# 4. 仕様解釈に関する補足

## 4.1 「壁が接触した瞬間」の解釈

仕様: 「壁がアクティブピースへ接触した瞬間、アクティブピースは操作対象ではなくなる」

実装: 壁が接触した後、ピースは右へ押し込まれ続ける。押し込めなくなった時点で固定。

解釈: 「操作対象ではなくなる」は「回転不能になる」を意味するのではなく、
「壁の動きに従って移動する状態になる」を意味すると解釈する。
プレイヤーは壁が接触した後でも回転可能（実装上の制約により回転しても壁に押される）。
この解釈が正しい場合、実装は仕様と一致する。

## 4.2 ゲームオーバー条件

仕様: 「新しいアクティブピースを初期位置から押し込めなくなった時点でゲームオーバー」

実装: `spawnPiece()` でスパン位置の衝突をチェック。衝突すれば GAME_OVER。

解釈: MVP として「スパン位置が占有されている＝配置できない」と判断するのは妥当。
より厳密には「フィールドのどこにでも配置できない」ことをチェックすべきだが、
MVP の範囲ではスパン位置のチェックで十分。
